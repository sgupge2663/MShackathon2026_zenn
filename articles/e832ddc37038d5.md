## **「朝、出社したら——メール作業、もう終わってました。」**

紙やPDFで届く価格改定や供給停止の通知。影響顧客の特定とメール作成の二度手間で午前中が潰れる。

そんな悲痛な声から考案された本システムは、AIがFAXの内容を読み解き、取引データから自動で宛先を特定し、メールの下書きまで完成させる、自律的なエージェントです。

## 1. 📋 課題提起と開発目的

### 1-1. ターゲットユーザーと背景
「朝8時、出社すると共有フォルダにFAXが8件」。これはヒアリングで語られた現場のリアルな風景です。本システムのターゲットは「**FAXを使用している業界（特に専門商社）の営業職**」です。現場担当者であるAIツール導入経験が少ない方を想定しています。彼ら・彼女らはメーカーと顧客の間で情報の伝達やモノの手配などを行う仲介役として立ち回り、通常1日1件未満のFAX受信が繁忙期には8件へ急増し、**1件15分**の手作業に追われています。


### 1-2. FAXがもたらす地味で重い業務負荷
実務において一番大変なのはメール文面の作成ではありません。対象商品と販売履歴、担当者の記憶を照合し「**この通知はどの顧客に関係するかを特定すること**」です。繁忙期にはこの確認作業だけで1件あたり**15分**、1日最大**8件で計2時間**もの時間を奪われます。

また、メーカーからの価格改定を見逃して旧価格で顧客へ連絡してしまい、自社に**逆ザヤの損失（自社の損失）** が発生するリスクと隣り合わせなのです。

:::message alert
「宛先を間違えたらどうしよう」というミスへの恐怖とプレッシャーが、毎日の現場担当者を深く疲弊させています。
:::


### 1-3. 既存ツールの限界と本システムの目的
IVRyやisanaなどの既存ツールはFAXの読み取りまでしか対応しておらず、1件15分かかる宛先特定やメール作成は人間が行う必要があります。時間に追われる営業事務担当者にとって、根本的な作業負担は手付かずのままです。

| ツール | 主な機能 | できないこと |
|---|---|---|
| **IVRy** | FAX内容のAI自動文字起こし・テキスト化、スマホ・PCでの送受信、クラウド保管・検索 | メールの作成 |
| **isana** | FAXの自動振り分け・自動返信、ステータス管理、メール・FAXの一元管理 | 影響顧客の特定、返信以外のメール送信 |
| **FAXion AI** | 上記に加え、購買履歴との照合による影響顧客の自動特定、メール自動生成、フィードバック学習、リマインド機能 | — |

本システムは、FAXの受信から宛先候補の自動提案、メール下書き生成までを一貫して行います。さらに価格改定期日前の自動リマインド機能により、顧客への**案内漏れをゼロ**にします。既存ツールでは届かない領域を担い、現場を救います。




## 2. ✨ 解決策となる主要機能

### 2-1. FAX通知対応エージェント（FAXion AI）の概要
本システムは、未だFAXが連絡手段として残る業界に向けた、価格改定などの通知を処理するAIエージェントです。単なる文字起こしではなく、顧客の購入履歴と照合して「**連絡すべき相手**」を自律的に判断・提案する「**影響顧客特定エージェント**」として機能します。


### 2-2. 影響顧客を特定する主要機能
本システムは以下の手順で、影響顧客の特定から学習までを自律的に行います。
1. **情報抽出と分類**: Azure Document IntelligenceでFAXをOCR処理し、GPT-4oが価格改定などの種別と対象商品を抽出します。
2. **宛先候補の自動提案**: 商品名と顧客購買履歴を照合し、過去の全購入実績から信頼度スコアを算出して宛先候補を提案します。
3. **判断理由の明示**: 優先度・顧客名・対象商品とともに「なぜ対象か」「推奨対応は何か」をリスト形式で提示し、人間の最終確認を助けます。
4. **フィードバック学習**: 提案された宛先を人間が削除すると履歴に記録し、次回同じメーカーのFAXが来た際は提案スコアを下げて再学習します。


## 3. 👤 利用手順とユーザー体験

### 3-1. 4画面エリアによる確認と送信
4つの画面エリア（一覧・原文・抽出・下書き）で以下5手順を行います。

![FAXion AIの操作画面](/images/image.png)

1. **FAX選択**: FAX一覧から、処理したいFAXを選びます。
2. **宛先確認**: AIが判断した宛先候補と信頼度スコアが自動表示されます。
3. **候補の精査**: 画面を確認し、不要な宛先を手動で削除します。
4. **保存・送信**: 人間がメールの下書き文章を確認し、メール下書きの保存もしくは即時送信を実行します。
5. **宛先候補削除の学習**: 同じメーカーの異なるFAXを受信・選択すると、AIが宛先候補削除履歴を学習しスコアを下げます。

### 3-2. 使うほど賢くなるフィードバックループ
AIが以下の手順で宛先候補を自動スコアリングして担当者に提示します。

1. **宛先候補削除の記録**: 担当者が候補を「却下」すると、顧客・商品の組み合わせとともに履歴に記録されます。
2. **履歴の学習・参照**: 同じ顧客・商品の組み合わせが次回のFAX処理で登場した際、AIが自動で過去の削除記録を参照します。
3. **提案順位への反映**: 削除履歴がある組み合わせは、提案スコアが引き下げられた状態で提示されます。この提案スコアの大小で優先順位が決まります。


:::message
この学習こそがエージェントの必然性です。
:::

### 3-3. 対応漏れを防ぐ自動リマインド機能
FAXion AIでは、**実施日の7営業日前（土日祝除く）** になると担当者へ自動でリマインドメールが送信されます。対応漏れや期日超過による**逆ザヤリスクを未然に防ぎます。**


## 4. 🏗️ システムアーキテクチャ

### 4-1. Azure中心の全体構成図
ホストPCに依存しないクラウド構成を採用しました。Azure Blob Storageを中心に処理とUIを分離し、常時稼働を実現しています。構成とフローは下図の通りです。
![アーキテクチャ図](/images/アーキテクチャ図.png)
*FAXion AI の全体構成。受信・AI処理・配信／通知の3ブロックがすべて Azure 上で完結する。*

FAXion AIは、ホストPCに依存せず**Azureだけで完結する常時稼働システム**です。処理は大きく「受信 → AI処理 → 配信・通知」の3ブロックに分かれます。

- **① 受信**：利用者はブラウザ（Container Apps 上の Streamlit UI）からFAXのPDFを投入。ファイルは Azure Blob Storage の `fax-inbox` コンテナに保存されます。
- **② AI処理**：PDF到着の瞬間に Event Grid 型の Blob Trigger が Azure Functions を起動。Document Intelligence でOCRし、Azure OpenAI（GPT-4o）で「カテゴリ・メーカー・実施日・対象製品・値上げ幅」を構造化抽出して、結果を `fax_queue.json` へ書き戻します。
- **③ 配信・通知**：UIが抽出結果と宛先候補を提示。人間が確認・編集したうえで、Microsoft Graph で**Outlook下書き保存**、または Azure Communication Services で**即時送信**します。加えて Timer Trigger が毎朝、実施日が7営業日前に迫った案件を自動でリマインドします。

Functions と UI は別サーバーで動きますが、共有ストレージに Blob Storage を据えることで両者が同じデータ（JSON・Excel）を読み書きでき、**特定のPCの稼働に縛られない構成**を実現しています。

### 4-2. 使用技術スタックと連携API

| レイヤー | 採用技術 | 役割 |
|---|---|---|
| UIホスティング | Azure Container Apps + Docker | Streamlit UI を公開URLで常駐 |
| フロントエンド | Streamlit | 確認・編集・送信のWeb画面 |
| ファイル監視 | Azure Functions（Event Grid 型 Blob Trigger） | PDF到着で自動起動（`watcher.py` の代替） |
| 共有ストレージ | Azure Blob Storage | PDF・JSON・Excel のクラウド共有 |
| OCR | Azure AI Document Intelligence（prebuilt-layout） | FAX画像 → テキスト化 |
| 構造化抽出 | Azure OpenAI GPT-4o | テキスト → JSON（カテゴリ・実施日 等） |
| 下書き・履歴確認 | Microsoft Graph API | Outlook下書き保存・送信履歴の参照 |
| 即時送信 | Azure Communication Services Email | 外部宛先への実配送 |
| 定期通知 | Azure Functions（Timer Trigger） | 実施日が近い案件の朝のリマインド |
| データ入出力 | openpyxl | 顧客・送信履歴 Excel の読み書き |

## 5. 🔧 開発時の技術的工夫

### 5-1. Azure移行による常時稼働化

*   **課題（失敗ルート）**: 当初はローカルフォルダを監視していましたが、ホストPCを閉じると全処理が停止してしまい、実運用に耐えませんでした。
*   **工夫（解決策）**: インフラ構築とUI開発で**役割分担**し、クラウドへの移行を実施しました。ファイル監視を**Azure Functions**のEvent Grid型Blob Triggerへ変更することで、クラウドでの常時稼働と高速な発火を両立しました。


### 5-2. GPT-4o構造化出力による抽出の安定化

*   **課題（失敗ルート）**: LLMはJSON形式が崩れたり分類が揺れたりして、後続のExcel照合が止まることがありました。
*   **工夫（解決策）**: `response_format` でJSON出力を強制し、さらにカテゴリを5種類に**排他定義**して必ず1つ選ばせることで分類を安定化。OCRと抽出は各3回リトライし、失敗時もログへ退避して処理全体は止めない設計にしました。



### 5-3. 誤送信を防ぐHuman in the Loop設計

*   **課題（失敗ルート）**: 完全自動で送信すると、宛先や文面を誤ったまま取引先に届く誤爆リスクが高く、実運用に耐えません。
*   **工夫（解決策）**: AIは宛先候補と下書きの**提案まで**、人間が内容を確認して送信ボタンを押す、と役割を分離。即時送信には「外部に届く」警告と**パスワード関所**を重ね、配送はACSEmailに任せて二重送信を防ぐ設計としました。


:::message alert
即時送信は取引先へ**実際にメールが届く**操作です。
誤送信は取り返しがつかないため、確認パネル・パスワード関所・受理ベースの二重送信防止という三重の歯止めで守っています。
:::
## 6. 📊 効果測定と検証結果

### 6-1. 業務時間の大幅削減の試算
ヒアリングから判明した「1件15分、繁忙期には1日8件」という重い業務負荷は、AIエージェントの導入により劇的に改善されます。人間が行うのは宛先とドラフトの最終確認のみとなるため、処理時間は**1/5から1/10**へと短縮されます。

これを月間20営業日で月次換算すると、**月約31時間**もの作業時間削減効果が生まれます。さらに、GPT-4oとAzure Document Intelligenceを利用することで、クラウドAPI利用料は1件あたり**約4円**で、繁忙期（月80件）でも月額たったの**約320円**です。
極めて低コストであり、圧倒的な費用対効果で現場の負担を解消します。

| | 従来方式 | AI活用後 | 改善率 |
|---|---|---|---|
| 1件あたり処理時間 | 15分 | 約1.5分 | 約90%削減 |
| 繁忙期1日あたり | 120分 | 約12分 | 約90%削減 |
| 月間作業時間（試算） | 約40時間 | 約4時間 | 月約36時間削減 |

### 6-2. 現場担当者による実証とフィードバック
実際のFAX利用者を対象としたヒアリングやユーザーテストを行ったところ、以下のフィードバックを得られました。

- 「メーカーからFAXが来るたびに、販売履歴のExcelを手動でフィルタをかけ、得意先への影響を確認していた。**その作業が無くなるのは嬉しい。**」ー商社・営業・FAX日常利用
- 「フィードバック学習のおかげで、もう取引のない仕入れ先が毎回候補に出てくる**ストレスが減りそう。** 」ー製造・営業・FAX日常利用
- 「FAXを無理に廃止せず、**そのまま活かしながらAIが処理を巻き取る設計**が魅力的。メール自動作成や確認作業の簡素化により、**既存のタスクフローに自然に組み込める**点が評価できる。」ー医療従事者・FAX日常利用


一方で
- 繁忙期に複数メーカーからFAXが重なったとき、**優先順位付けや一括処理をどう捌くか**
- FAX受領確認のやり取り（送信→確認電話→受信→印刷）が煩雑で、**双方への自動通知で省力化**したい
- FAX to FAXの業界・現場では、**メール文面だけでなくFAX文面の生成にも対応**してほしい
- 単なる連絡の効率化ツールにとどまらず、**コア業務のデータベース（一元管理システム）の入り口として機能**させることで、プロダクトの市場価値はさらに高まるのではないか

といった運用上の課題も明らかになっており、今後の機能拡張に反映する予定です。

## 7. 🚀 今後の展望と追加機能

### 7-1. ユーザーの声から見えた次の課題
実証・ヒアリングを通じて２つの共通した要望が浮かび上がりました。

1．**他業種への横展開**: 「FAXを受け取り、影響範囲を特定し、アクションを起こす」業務パターンが残る場所であれば業界を問わずそのまま横展開することができます。現在の「値上げ・出荷停止などのカテゴリを事前に定義し、その枠内でFAX内容を分類・処理する設計」から「カテゴリ定義を撤廃し、AIが文書を読んで内容・意図・必要なアクションを自律的に判断する設計」へ移行することで、想定外の通知パターンに対応することができます。
2．**受領確認の自動化**: 商社・製造にとどまらず、医療・化学・建設など「FAX×業務連絡」が残る業界すべてに同様の課題があります。業種ごとの専門対応（SDS改訂通知・医療部材の欠品連絡など）を順次追加予定です。

### 7-2. エージェント機能の拡張
利用者がAIを意識しない究極のUXを目指し、以下を拡張予定です。

- カテゴリ設計方法の変更
- Outlookカレンダーの自動登録
- 通知種別に応じた動的ツール選択
- マルチエージェントによる専門的分業
- FAX受領確認通知
