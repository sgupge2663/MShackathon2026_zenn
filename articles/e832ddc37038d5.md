## 1. 📋 課題提起と開発目的

### 1-1. ターゲットユーザーと背景
「朝8時、出社すると共有フォルダにFAXが8件」。これはヒアリングで語られた現場のリアルな風景です。本システムのターゲットは「**FAXを使用している業界（特に専門商社）の営業職**」です。現場担当者であるAIツール導入経験が少ない方を想定しています。彼ら・彼女らはメーカーと顧客の間で情報の伝達やモノの手配などを行う仲介役として立ち回り、通常1日1件未満のFAX受信が繁忙期には8件へ急増し、**1件15分**の手作業に追われています。


### 1-2. FAXがもたらす地味で重い業務負荷
実務において一番大変なのはメール文面の作成ではありません。対象商品と販売履歴、担当者の記憶を照合し「**この通知はどの顧客に関係するかを特定すること**」です。繁忙期にはこの確認作業だけで1件あたり**15分**、1日最大**8件で計2時間**もの時間を奪われます。

また、メーカーからの価格改定を見逃して旧価格で顧客へ連絡してしまい、自社に**逆ザヤの損失**が発生するリスクと隣り合わせなのです。

:::message alert
「宛先を間違えたらどうしよう」というミスへの恐怖とプレッシャーが、毎日の現場担当者を深く疲弊させています。
:::


### 1-3. 既存ツールの限界と本システムの目的
IVRyやisanaなどの既存ツールはFAXの読み取りまでしか対応しておらず、1件15分かかる宛先特定やメール作成は人間が行う必要があります。時間に追われる営業事務担当者にとって、根本的な作業負担は手付かずのままです。

| ツール | 主な機能 | できないこと |
|---|---|---|
| **IVRy** | FAX内容のAI自動文字起こし・テキスト化、スマホ・PCでの送受信、クラウド保管・検索 | 影響顧客の特定、メール下書き生成 |
| **isana** | FAXの自動振り分け・自動返信、ステータス管理、メール・FAXの一元管理 | 影響顧客の特定、メール下書き生成 |
| **FAXion AI** | 上記に加え、購買履歴との照合による影響顧客の自動特定、メール下書き生成、フィードバック学習 | — |

本システムは、FAXの受信から宛先候補の自動提案、メール下書き生成までを一貫して行います。さらに価格改定期日前の自動リマインド機能により、顧客への**案内漏れをゼロ**にします。既存ツールでは届かない領域を担い、現場を救います。




## 2. ✨ 解決策となる主要機能

### 2-1. FAX通知対応エージェント（FAXion AI）の概要

> **「朝、出社したら——返信文、もう書いてありました。」**

本プロダクトは、未だFAXが連絡手段として残る業界に向けた、価格改定などの通知を処理するAIエージェントです。単なる文字起こしではなく、顧客の購入履歴と照合して「**連絡すべき相手**」を自律的に判断・提案する「**影響顧客特定エージェント**」として機能します。


### 2-2. 影響顧客を特定する主要機能
本エージェントは以下の手順で、影響顧客の特定から学習までを自律的に行います。
1. **情報抽出と分類**: Azure Document IntelligenceでFAXをOCR処理し、GPT-4oが価格改定などの種別と対象商品を抽出します。
2. **宛先候補の自動提案**: 商品名と顧客購買履歴を照合し、過去の全購入実績から信頼度スコアを算出して宛先候補を提案します。
3. **判断理由の明示**: 優先度・顧客名・対象商品とともに「なぜ対象か」「推奨対応は何か」をリスト形式で提示し、人間の最終確認を助けます。
4. **フィードバック学習**: 提案された宛先を人間が削除すると履歴に記録し、次回同じメーカーのFAXが来た際は提案スコアを下げて再学習します。


## 3. 👤 利用手順とユーザー体験

### 3-1. 4画面エリアによる確認と送信
4つの画面エリア（一覧・原文・抽出・下書き）で以下5手順を行います。

![FAXion AIの操作画面](/images/4-pane-UI.png)

1. **FAX選択**: FAX一覧から処理したいFAXを選び、AIが内容を自動抽出します。
2. **宛先確認**: AIが判断した宛先候補と信頼度スコアが自動表示されます。
3. **候補の精査**: 画面を確認し、不要な宛先を手動で削除します。
4. **保存・送信**: 人間がメールの下書き文章を確認し、メール下書きの保存もしくは即時送信を実行します。
5. **宛先候補削除の学習**: 同じメーカーの異なるFAXを受信・選択すると、AIが宛先候補削除履歴を学習しスコアを下げます。

### 3-2. 使うほど賢くなるフィードバックループ
AIが以下の手順で宛先候補を自動スコアリングして担当者に提示します。

1. **宛先候補削除の記録**: 担当者が候補を「却下」すると、顧客・商品の組み合わせとともに履歴に記録されます。
2. **履歴の学習・参照**: 同じ顧客・商品の組み合わせが次回のFAX処理で登場した際、AIが自動で過去の削除記録を参照します。
3. **提案順位への反映**: 削除履歴がある組み合わせは、提案スコアが引き下げられた状態で提示されます。この提案スコアの大小で優先順位が決まります。


:::message
この学習こそがエージェントの必然性です。
:::

### 3-3. 対応漏れを防ぐ自動リマインド機能
FAXion AIでは、**実施日の7営業日前（土日祝除く）** になると担当者へ自動でリマインドメールが送信されます。対応漏れや期日超過による**逆ザヤリスクを未然に防ぎます。**

### 4-2. 使用技術スタックと連携API
本システムの基盤となる主要なクラウドサービスとAPIの構成です。要件であるAzureエコシステムを全面採用し、非定型文書からの正確な情報抽出と、既存の業務環境へのシームレスな連携を重視して選定しました。

| 役割 | 技術 | 採用理由 |
|---|---|---|
| フロントエンド・実行環境 | Streamlit + Azure Web Apps | Python実装のUIを短期間で24時間稼働のWebアプリ化するため |
| 監視・トリガー | Azure Functions (Blob Trigger) | PDFのアップロードを検知して即座にOCRと情報抽出を自動起動するため |
| データストレージ | Azure Blob Storage | 独立したUIとFunctionsの間でファイルや連携データを安全に共有するため |
| OCR（文字認識） | Azure Document Intelligence | 非定型なFAX画像から表構造を保持したまま高精度にテキストを抽出するため |
| LLM（情報抽出・生成） | Azure OpenAI (gpt-4o) | JSONスキーマ出力機能により、JSON形式での安定した構造化抽出を行うため |
| 外部連携（メール・宛先） | Microsoft Graph API | 現場のExcel顧客データを参照し、Outlookへメール下書きを直接保存するため |

## 5. 🔧 開発時の技術的工夫🟡

### 5-1. Azure移行による常時稼働化
- **課題**: 当初の実装では、ホストPCを閉じた瞬間に全機能が停止する問題がありました。
- **工夫**: Azure Blob StorageとAzure Functions (Blob Trigger)を組み合わせ、監視プロセスをクラウド化しました。

これをUI開発の小島と、インフラ構築の林田で役割分担し、**24時間常時稼働**への移行を達成しました。

### 5-2. GPT-4o構造化出力と Graph API連携
- **課題**: AIの出力ブレによる処理失敗やGraph APIの初回認証エラー。
- **工夫**: プロンプト指示に加え、以下の通りJSONスキーマを指定して出力を制御。

これらの失敗を解決し、Excelとの安定したデータ連携を実現しました。 
## 6. 📊 効果測定と検証結果

### 6-1. 業務時間の大幅削減の試算
ヒアリングから判明した「1件15分、繁忙期には1日8件」という重い業務負荷は、AIエージェントの導入により劇的に改善されます。人間が行うのは宛先とドラフトの最終確認のみとなるため、処理時間は**1/5から1/10**へと短縮されます。

これを月間20営業日でマクロ換算すると、**月約31時間**もの作業時間削減効果が生まれます。さらに、GPT-4oとAzure Document Intelligenceを合わせたクラウドAPI利用料は1件あたり**約4円**で、繁忙期（月80件）でも月額たったの**約320円**です。
極めて低コストであり、圧倒的な費用対効果で現場の負担を解消します。

| | 従来方式 | AI活用後 | 改善率 |
|---|---|---|---|
| 1件あたり処理時間 | 15分 | 約1.5分 | 約90%削減 |
| 繁忙期1日あたり | 120分 | 約12分 | 約90%削減 |
| 月間作業時間（試算） | 約40時間 | 約4時間 | 月約36時間削減 |

### 6-2. 現場担当者による実証とフィードバック
実際のFAX利用者を対象としたヒアリングやユーザーテストを行ったところ、以下のフィードバックを得られました。

- 「メーカーからFAXが来るたびに、販売履歴のExcelを手動でフィルタをかけ、得意先への影響を確認していた。**その作業が無くなるのは嬉しい。**」ー商社・営業・FAX日常利用
- 「フィードバック学習のおかげで、もう取引のない仕入れ先が毎回候補に出てくる**ストレスが減りそう。** 」ー製造・営業・FAX日常利用
- 「FAXを無理に廃止せず、**そのまま活かしながらAIが処理を巻き取る設計**が魅力的。メール自動作成や確認作業の簡素化により、**既存のタスクフローに自然に組み込める**点が評価できる。」ー医療従事者・FAX日常利用


一方で
- 繁忙期に複数メーカーからFAXが重なったとき、**優先順位付けや一括処理をどう捌くか**
- FAX受領確認のやり取り（送信→確認電話→受信→印刷）が煩雑で、**双方への自動通知で省力化**したい
- FAX to FAXの業界・現場では、**メール文面だけでなくFAX文面の生成にも対応**してほしい
- 単なる連絡の効率化ツールにとどまらず、**コア業務のデータベース（一元管理システム）の入り口として機能**させることで、プロダクトの市場価値はさらに高まるのではないか

といった運用上の課題も明らかになっており、今後の機能拡張に反映する予定です。

## 7. 🚀 今後の展望と追加機能

### 7-1. ユーザーの声から見えた次の課題
実証・ヒアリングを通じて３つの共通した要望が浮かび上がりました。

1．**他業種への横展開**: 医療現場からは「FAX送信後に確認電話をしている」という声が寄せられました。FAX到着時にリアクション一つで双方が受領確認できる機能と、メールでの記録を組み合わせることで、業界を問わずトラブル防止につながります。
2．**受領確認の自動化**: 商社・製造にとどまらず、医療・化学・建設など「FAX×業務連絡」が残る業界すべてに同様の課題があります。業種ごとの専門対応（SDS改訂通知・医療部材の欠品連絡など）を順次追加予定です。
3．**コア業務のデータベース化**: 寺院・葬儀社のように、FAXで届く情報を既存の管理システムへ自動連携し、年忌法要案内などの継続タスクへシームレスに引き継ぐ仕組みは、FAX文化が根強い業界全体に応用できます。
